## Lessons Learned

### Problem 1: Stale/Dead Container from Prior Run
When first attempting `docker compose up` after the systemd service was created, Docker failed with:
```
Error response from daemon: container is marked for removal and cannot be started
```

**Root cause:** A prior attempt to run `neo4j_viz/docker-compose.yml` had left a container (`f3749bb7f639_paper-processor-neo4j`) in a "marked for removal" state. Attempting to recreate the container while the old one was stuck in cleanup caused a race condition.

**Fix:** 
1. Ran `docker container prune -f` to remove all stopped containers and clean up the orphaned container.
2. Ran `docker system prune -f` to prune all unused images, networks, volumes, and build cache.
3. Removed the obsolete `version: '3.8'` line from `neo4j_viz/docker-compose.yml` (deprecated in newer Docker Compose).
4. Restarted the systemd service: `sudo systemctl restart paper-processor-neo4j.service`.

**Prevention:** Always use `docker compose down -v` when stopping a compose stack intentionally, not just `^C` or `kill`. Consider adding a pre-flight `ExecStartPre=/usr/bin/docker compose down` in the systemd unit if races become common.

### Problem 2: Permission Denied on Volume Directories
After stopping the service, attempted to clean old data directories with `rm -rf data logs import plugins`. This failed with many `Permission denied` errors:
```
rm: cannot remove 'data/transactions/neo4j/neostore.transaction.db.283': Permission denied
rm: cannot remove 'data/dbms/auth.ini': Permission denied
[…]
```

**Root cause:** Neo4j container runs as uid 7474 (internal to the container), and Docker mounts these directories with that ownership. The local `jeb` user does not own them, so `rm` lacks write permission.

**Fix:**
1. Used `sudo rm -rf data logs import plugins` to remove the old volumes.
2. Also provisioned `jeb` in the `docker` group (`sudo usermod -aG docker jeb`) so future `docker` and `docker compose` commands don't require sudo. This is optional but convenient for interactive use.

**Prevention:** When stopping Neo4j, consider a `docker compose down -v` which Docker handles cleanly as root, rather than attempting manual removal of mounted volumes.

## Future Notes & Directions

### Security
- **Change default credential:** The hardcoded `NEO4J_AUTH=neo4j/password123` in `docker-compose.yml` is a dev convenience, not production-safe. Future work should:
  - Move `NEO4J_AUTH` to a `.env` file (gitignored) or systemd environment variable.
  - Document the credential-rotation procedure (Neo4j's `:admin` user cannot be deleted, only password reset via Cypher).
  - Add firewall notes if this service is ever exposed beyond localhost.

### Stability & Observability
- **Pin the Neo4j version:** Currently `image: neo4j:latest` will auto-upgrade on pull, potentially breaking compatibility. Pin to a specific version tag (e.g., `neo4j:5.17.0`) for reproducibility.
- **Add startup health-check:** If downstream consumers (e.g., `paper_processor_dir.py`'s periodic sync thread) race the container start, add an `ExecStartPre` that polls the Bolt port before considering the service "up". Currently the service is marked `active` before Neo4j is actually ready (~5 seconds post-container-start).
- **Monitor sync delays:** `paper_processor_dir.py` checks port 7687 every 300 seconds. If Neo4j is briefly down, this thread continues silently. Consider adding a counter/alert for missed syncs.

### Deployment & Scale
- **Docker Compose version:** The removed `version: '3.8'` line is optional in modern Compose (v1.27.0+) but was historically required. Document the minimum Docker Compose version supported.
- **Memory limits:** Current systemd unit caps memory at 4GB. Monitor actual usage under typical workloads (number of papers synced, graph size). Neo4j can require more for large graphs; consider making this a tunable parameter in future.
- **Multi-user access:** Dashboard currently serves at `localhost:7474` (bound to 127.0.0.1 in Docker). If shared team access is needed, reverse-proxy through nginx (with auth) or adjust Docker bindings — currently closed by design.

## Dependency Notes
- `paper_processor_dir.py` hardcodes Bolt port polling (line 1220, `:7687`). If the port is ever changed, this script must be updated in parallel.
- The periodic sync thread (line 1237) runs every 300 seconds. This blocks if Neo4j is down, so startup order matters — Neo4j should boot before (or at least early in) multi-user.target.
