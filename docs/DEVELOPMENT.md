# Development Guide

## Setup

```bash
# Python deps
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install ruff          # linter

# Rust (wizard)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
cd wizard && cargo build
```

## Running the pipeline locally

```bash
# Dry-run: list papers and their completion status
python3 paper_processor.py --list

# Single paper, force small model
python3 paper_processor.py --paper "test.pdf" --model deepseek-r1:8b

# Reprocess only diagrams
python3 paper_processor.py --reprocess diagrams
```

## Linting

```bash
ruff check paper_processor.py       # lint
ruff format paper_processor.py      # auto-format

cd wizard && cargo clippy           # Rust lint
cd wizard && cargo fmt              # Rust format
```

CI runs both on every push (see `.github/workflows/lint.yml`).

## Adding a new prompt stage

A "stage" is a named prompt that runs against each paper and writes an output
file. Stages are defined in two places.

### 1. Add the prompt

In `paper_processor.py`, add an entry to the `PROMPTS` dict (around line 227):

```python
PROMPTS = {
    # existing stages …
    "mystage": textwrap.dedent("""\
        Your prompt text here.
        Use section headers for structured output.
    """),
}
```

### 2. Add the output filename and metadata key

In `PaperProcessor.process_paper()`, follow the pattern of the existing stages.
Each stage:
1. Checks `metadata["sections"]["mystage"]["completed"]` — skip if True.
2. Calls `self.backend.generate(model, PROMPTS["mystage"], text)`.
3. Writes the result to `output_dir / "05_mystage.md"`.
4. Sets `metadata["sections"]["mystage"]["completed"] = True` and saves.

### 3. Register the stage name in the CLI

Add `"mystage"` to the `choices=` list for `--reprocess` in `main()`:

```python
ap.add_argument(
    "--reprocess", default=None,
    choices=["summary", "logic", "cpp", "diagrams", "extras", "mystage", "all"],
    …
)
```

### 4. Handle `--reprocess all`

Search for the block that clears completion flags when `args.reprocess == "all"`
and add `"mystage"` to that list.

## Adding a new backend

Backends are abstracted behind the `Backend` class. To add a new one:

### 1. Add the backend name to the CLI

```python
ap.add_argument(
    "--backend", choices=["ollama", "openclaw", "mybackend"], …
)
```

### 2. Implement the generate method

In `Backend.generate()`, add a branch:

```python
elif self.backend == "mybackend":
    return self._generate_mybackend(model, prompt, text)
```

Then implement `_generate_mybackend()` following the same signature as
`_generate_ollama()`: accepts `model: str`, `prompt: str`, `text: str`,
returns `str` (the model's response).

The method should:
- Stream or batch-request the model.
- Raise `_ShutdownRequested` if `_shutdown.is_set()` during a long call.
- Return an empty string on failure (the pipeline treats that as a skippable error).

## Extending the wizard (Rust)

The wizard is a Ratatui app in `wizard/src/main.rs`. Tabs are implemented as
enum variants with their own render and input-handler functions.

### Adding a tab

1. Add a variant to the `Tab` enum.
2. Add a `render_<tab>()` function following the existing pattern.
3. Add an arm to the `handle_key()` match for your tab's keybindings.
4. Add the tab label to the tab bar render in `render_tabs()`.

### Ollama health probe

The wizard polls `http://localhost:11434/api/tags` via `ureq` to check whether
Ollama is reachable. This lives in `check_ollama_health()`. If you add a new
backend, add a similar probe function here.
